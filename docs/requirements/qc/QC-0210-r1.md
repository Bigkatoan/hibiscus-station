# QC report: Hibiscus Station hotfix 0.2.10, round 1

* **Verdict: FAIL.** The customer's complaint is fixed. On the installed artifact, every recorded
  episode can be seen during recording, during the save, right after Stop, after the save and after
  a restart. The Datasets list and the dataset page give no 500 in normal use or after a crash.
  D-26 (deleting robot profiles) passes every check.
  Two defects block the release under the blocking rule:
  * **QH-1 (Medium, regression on this branch).** If `meta/info.json` holds a very large
    `total_episodes`, opening the dataset page makes the Station use memory without limit. The
    Station is OOM-killed, or QC's 4 GB guard kills it after 2.5 s. 0.2.9 answers the same request
    with 200 in 0.19 s.
  * **QH-2 (Medium, pre-existing in 0.2.9).** "Append to an existing dataset" answers
    **500 Internal error** when the dataset's `meta/info.json` is empty, cut short, or not an object.
    A Station killed while LeRobot rewrites `info.json` leaves such a file, and the dataset still
    shows in the append list.
  * Four non-blocking findings: QH-3 to QH-5 (Low) and QH-6 (a flaky CI test).
* **Artifact tested:** branch `hotfix/0.2.10`, commit `b20054480da767e96d3160672ee3de5421b5e5c0`.
  This is 59e0f37 plus D-26.

### QH-1: unbounded memory on the dataset page (regression)
* **Repro:**
  1. Copy any dataset and set `"total_episodes": 1000000000` in its `meta/info.json`.
  2. Run `GET /api/v1/datasets` and get 200.
  3. Open `/datasets/<name>` (or run `GET /api/v1/datasets/<name>`).
* **Expected:** 200 or a 4xx, as quickly as 0.2.9, with the menu kept.
* **Actual:** no answer. Station RSS reached 4163 MB in 2.5 s, and QC killed it. On 59e0f37 the
  Station process vanished with no log line (an OOM kill). The page then loses the Station, and any
  recording in progress would be lost with it.
* **Same request on 0.2.9:** 200 in 0.19 s, with a peak of 154 MB.
* **Cause:** `episodes()` builds `set(range(total))`, and `total` comes from info.json with no upper
  bound (`_count`).
* **Field likelihood:** low; it needs a corrupted file. But one bad file takes down the whole
  Station, so it is a release blocker under the rule.
* **Evidence:** `evidence/0210-r1/QH-1-memory.txt`.

### QH-2: 500 on append into a dataset whose info.json is broken (pre-existing)
* **Repro:**
  1. In a dataset, make `meta/info.json` empty (`printf '' > info.json`). A truncated `{…`, `[]`,
     or `"features": {"action": null}` give the same result.
  2. Record page → "Append to an existing dataset" → pick it. It is listed with 0 episodes.
  3. Start recording.
* **Expected:** a 4xx with a clear message (like `dataset_not_finalized`), and no file changed.
* **Actual:** `500 internal_error`. The detail is `JSONDecodeError` or `AttributeError`, raised in
  `recorder.py open()` / `_norm_features`. 4 tracebacks on 0.2.10.
* **On 0.2.9:** the same 500. On 0.2.9 the dataset page also gives 500; 0.2.10 fixed the page but
  not the append.
* **Field likelihood:** LeRobot rewrites info.json in place on every saved episode (the dev's root
  cause 3), so a crash in that window leaves exactly this file. The CHANGELOG says appending to a
  crash-left dataset "answers 409, never 500".
* **Evidence:** `evidence/0210-r1/QH-2-append-500-traceback.txt`.

### QH-3: misleading "The other episodes are fine"
* **Repro:**
  1. Kill -9 the Station while it records (3, 4 or 12 episodes saved).
  2. Restart and open the dataset.
* **Expected:** wording that is true when every episode is affected.
* **Actual:** every row says "Cannot be read: … The other episodes are fine." / "… Các tập khác vẫn
  dùng được.", while all rows are unreadable. The telemetry of these episodes can be read through
  the API, but the UI disables the episode button, so the user cannot open it.
* **Evidence:** `static_datasets_crasha-*.png`, `static_datasets_crashb-en-390-dark.png`.

### QH-4: misleading replay error on a crash-left dataset
* **Repro:** run `POST /sessions/replay {dataset: crasha, episode: 0}` (or episode 99) after
  the crash.
* **Expected:** a message that the dataset was not finished and cannot be replayed.
* **Actual:** `409 busy`, "this episode is still being saved; try again when the dataset is
  finalized". The dataset will never be finalized. The UI disables Replay on these rows, so only
  the API shows this.

### QH-5: wrong error class on an unreadable info.json (pre-existing)
* **Repro:** `chmod 000 meta/info.json`, then append.
* **Actual:** `502 bus_error`, "start session: [Errno 13] Permission denied …". The same happens on 0.2.9.

### QH-6: flaky Windows timing test (CI)
* Run 44699885224 attempt 1, job windows:
  `tests/test_programs_safety.py::test_deadman_loss_while_the_program_waits` measured 1.61 s
  against a 1.5 s limit.
* Attempt 2 passed. The product is not affected. The test margin is too tight for the Windows runner.

## Observations (no defect id)
* **O-1: episodes of a crash-left dataset cannot be viewed.** A dataset left by a crash
  (kill -9, power loss, or a Windows console closed without Ctrl+C) keeps its episodes counted, but
  each one is "unreadable". The episode rows were in LeRobot's memory, and the data parquet has no
  footer. This also holds for datasets made by 0.2.9. 0.2.10 makes it visible and safe, but it
  does not recover the episodes.
  * The "can't view recorded episodes" complaint is resolved for normal sessions, but **not for a
    session the Station did not close**.
  * Ctrl+C on Linux finalizes correctly. QC could not check how closing the console window on
    Windows ends the session.
  * Customer-level decision: accept this for the hotfix, or ask for recovery in M1.
* O-2: right after Start, before the first episode is saved, the dataset page says "There is no
  dataset … on this computer". This is not a 500, and it is the same as 0.2.9.
* O-3: the Record page's append list still offers crash-left datasets; it then shows the 409 card.
