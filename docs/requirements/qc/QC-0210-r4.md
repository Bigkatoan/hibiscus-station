## QH-9 re-test (installed app, API)

* **Setup:** we copied a consistent, finalized dataset (6 episodes in 3 data / 3 meta / 3×2 video
  files, 180 frames) and changed one thing per copy. For each copy we read the list and the detail,
  then appended 1 episode through `POST /sessions/record` with a connected robot.
* **Result:** every inconsistent copy shows as not finalized and is refused with **409
  `dataset_unreadable`**, and the files are **byte-identical**. The consistent copy still appends.
* **Evidence:** `r4_qh9.txt`.

| Change | List / detail | Reason shown | Append | Files |
|---|---|---|---|---|
| `total_episodes` 0 | not finalized / not finalized | "no episodes saved yet" | 409 `dataset_unreadable` | identical |
| `total_episodes` 1 | not / not | "inconsistent: meta/info.json counts 1 episodes, meta/episodes holds 6" | 409 | identical |
| `total_episodes` 3 | not / not | "… counts 3 episodes, … holds 6" | 409 | identical |
| `total_episodes` 8 (more than real) | not / not | "… counts 8 episodes, … holds 6" | 409 | identical |
| `total_frames` 179 (−1) | not / not | "… counts 179 frames, the episodes hold 180" | 409 | identical |
| `total_frames` 181 (+1) | not / not | "… counts 181 frames, …" | 409 | identical |
| Episode index gap (last row 5 → 10 in `meta/episodes`) | not / not | "the episode indexes are not 0..N-1 without gaps" | 409 | identical |
| A data file deleted | not / not | "missing files: data/chunk-000/file-002.parquet" | 409 | identical |
| A video file deleted | not / not | "missing files: videos/observation.images.front/…" | 409 | identical |
| **Consistent copy** | **finalized / finalized** | none | **200**, 6 → 7 episodes, still finalized, all rows saved | changed as expected |

## List speed (about 60 datasets)

| Build | 61 datasets (25 × 15 episodes, 25 × 23 episodes, 11 fixtures), 12 calls | Detail of one dataset |
|---|---|---|
| 0.2.10 @ 1e4071f | first 0.372 s, median 0.372 s, max 0.384 s | 0.011 s |
| 0.2.9 (published) | median 0.041 s | – |

* The list is about 9 times slower (about 6 ms per dataset), because it reads `meta/episodes` of
  every finalized dataset on every call.
* At about 60 datasets this is still well under 0.5 s, so it is not blocking.
* Logged as **M1-4**: cache the result by the files' mtimes, or check consistency only on the
  detail page and on append. With hundreds of datasets the Datasets page would take seconds.
* Evidence: `list_speed.txt`.
