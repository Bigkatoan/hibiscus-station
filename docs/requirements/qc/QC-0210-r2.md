# QC report: Hibiscus Station hotfix 0.2.10, round 2

* **Verdict: FAIL** under the blocking rule "any 500". QH-1 to QH-5 are **all fixed** on the installed
  artifact, and nothing regressed.
  * The customer's complaint stays fixed: every recorded episode shows during recording, after a
    save, after a restart, after a crash, and after an upgrade from 0.2.9. D-26 still passes.
  * Two **500s that already exist in 0.2.9** remain. Both need a hand-edited `meta/info.json`, which
    neither LeRobot nor a crash can produce:
    * **QH-7 (Medium, blocking: a 500 on the list):** if a single dataset has `features` that is
      not an object, or `total_episodes: Infinity`, `GET /datasets` answers 500. The Datasets page
      then says "Station hit an internal error" and hides **every** dataset. The menu stays.
    * **QH-8 (Low, blocking: a 500 on replay):** Replay answers 500 when `fps` is `Infinity` or
      `0`, or when `features.action.names` has the wrong length or type.
  * We confirmed both are in 0.2.9: the same list / replay 500s appear there, plus many more.
  * **QH-7 and QH-8 are candidates for a customer waiver** (pre-existing, exotic). The other way is
    a small fix: catch any exception per dataset in `summary` / `list_datasets` and in
    `load_episode_actions`, and answer `dataset_unreadable`.
* **Artifact tested:** `hotfix/0.2.10` at `3e9afd43f030ecb320cfa59b0a079c1c8b0ef314`.
  * We cloned that commit fresh and built the UI (`pnpm install --frozen-lockfile`, `make web`; the
    CSP and locale-guard checks passed). `uv build --wheel` gave
    `hibiscus_station-0.2.10-py3-none-any.whl`, sha256
    `41d8773392e382bb15102ef3475ec8ee314fdb8b620bb97d3ac17318c583d1d1`, with 190 UI files.
  * We installed it with `uv tool install --python 3.12` into an empty `UV_TOOL_DIR`. It runs as
    `hibiscus-station --mock`; the D-26 checks also used real mode.
* **CI:** run 44708728585 for this exact SHA, attempt 1, succeeded with **8/8 jobs**: deploy, web,
  python, image, wheel, windows, e2e, macos. We checked it with `gh api`.
* **Rig:** the same as round 1: per-home `HF_HOME`, the Hub trap on `HF_ENDPOINT`, Playwright

**Precedence (append into a crash-left dataset with a different camera setup).** We connected a
profile with one camera and appended to `crasha`. The answer is `422 dataset_incompatible`, and the UI
shows "This dataset does not match the robot (motors or cameras differ)." The message is true, and
nothing is changed. It is not the most helpful message: a user who restores the camera setup only
reaches the next refusal (`dataset_not_finalized`), and this card has no "Record into a new dataset"
offer. This is not a regression and not a 500, so it goes to the **M1 backlog (M1-1)**.

| ID | Sev | Blocking | Origin | Summary |

| QH-7 | Medium | **yes** (500) | pre-existing (0.2.9: the same and more) | One dataset whose `features` is not an object (true, number, string, list), or whose `total_episodes` is `Infinity`, makes `GET /datasets` and its own detail answer 500 (AttributeError in `hibiscus.recording.check_recording`, OverflowError). Replay is enabled in the UI on these saved rows. |
| QH-6 | Low | no | CI flake (round 1) | The Windows dead-man timing test. Attempt 1 of this round's CI passed; the CHANGELOG lists it as a known test issue. |

* **QH-7 repro:**
  1. Copy a dataset.
  2. In its `meta/info.json`, set `"features": [1]` (or `"total_episodes": Infinity`).
  3. Open Datasets.
  * **Expected:** the list shows every dataset, and the damaged one shows as not finalized or unreadable.
  * **Actual:** 500, and the page shows no dataset.
  * Evidence: `r2-list500-en-1280-light.png`, `fuzz_info_0210.txt` against `fuzz_info_029.txt`.
* **QH-8 repro:**
  1. Set `"fps": 0` (or `Infinity`, or `features.action.names: ["a"]`).
  2. Press Replay on a saved row.
  * **Expected:** 409 `dataset_unreadable`.
  * **Actual:** 500.
  * Evidence: `fuzz_info_*.txt`.
* **Fuzz summary:** each top-level key, feature and feature field of info.json was set to 14 hostile
  values against list / detail / telemetry / replay. On 0.2.10, **16 mutations** still raise an
  unhandled error: 9 in list/detail and 7 in replay (plus fps 0, seen live). On 0.2.9 there are
  36 list/detail failures and 55 replay failures. Every 0.2.10 case also fails on 0.2.9, so none
  is a regression. Telemetry has none on either version.

### M1 backlog (not blocking: exotic, not a regression, not a 500, no data loss)
* **M1-1:** append into a crash-left dataset whose camera setup differs answers 422
  `dataset_incompatible` with no "Record into a new dataset" offer. Better: check
  "not finalized / unreadable" first, or offer a new dataset on 422 as well.
* **M1-2:** with `fps: Infinity` / `NaN` / a huge or negative number in info.json, the dataset still
  shows as finalized. Replay is accepted with fps 1e300, -5, "30" or true (it starts and runs at an
  absurd rate). It should be refused as `dataset_unreadable`, like append.
* **M1-3:** with a broken `features` the dataset still lists 6 "saved" rows; in detail the row data
  is shown from the disk. This is acceptable, but upload gating relies on `finalized`, which is
  correctly false.
