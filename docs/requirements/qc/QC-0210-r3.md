# QC report: Hibiscus Station hotfix 0.2.10, round 3

* **Verdict: FAIL** under the scope rule, on one data-loss defect that already exists in 0.2.9:
  **QH-9 (Medium, data loss).**
  * Trigger: a hand edit of `meta/info.json` that lowers `total_episodes` below the number of
    episodes on disk (0, or 3 when 9 exist).
  * Append is then accepted, and LeRobot overwrites the earliest data file: in our run, episodes
    1 and 2 were lost.
  * 0.2.9 does the same.
  * Neither LeRobot nor a crash writes such a file. A crash-left dataset is refused correctly.
  * This is the only blocker. It is a **waiver candidate**, and a small guard would remove it
    (see QH-9).
* **Everything else passes:**
  * QH-7, QH-8, M1-1 and M1-2 are fixed.
  * QC's API fuzz: 825 mutations × list / detail / healthy neighbour / telemetry / append / replay,
    with **0 5xx and 0 timeouts**. Refused calls left the files byte-identical, and the healthy
    neighbour dataset stayed byte-identical.
  * The dev's `tests/test_info_fuzz.py` passes.
  * The regression pass shows no regression. The customer's complaint stays fixed.
* **Artifact tested:** `hotfix/0.2.10` at `2893a2911de3b8504b625a84b572b3fccbb1fd11`.
  * We cloned it fresh and built the UI (the CSP and locale-guard checks passed).
  * `uv build --wheel` gave `hibiscus_station-0.2.10-py3-none-any.whl`, sha256
    `93af71a1ad0ba639cbfd7869e33178c3655e6cc5dbc97773e3dbe575f303ba81`, with 190 UI files.
  * We installed it with `uv tool install --python 3.12` into an empty tool dir and tested
    `hibiscus-station --mock` (real mode for D-26).
* **CI:** run 44714828911 for this SHA, attempt 1, succeeded with **8/8 jobs** (`gh api`).
* **Rig:** as in round 2, plus the published v0.2.9 wheel for the upgrade and for the
  "pre-existing" checks. Date: 2026-11-20. QC is independent.

## Fuzz

* **QC's own fuzz through the installed app** (`scripts/fuzz_api.py`):
  * **Setup:** a running mock Station. Each top-level key, feature and feature field of
    info.json was set to 16 values each (null, true, false, 0, -1, 1.5, 1e30, ±Infinity, NaN, "x",
    "", [], [1], {}, {"a":1}). We added two wrong-length/type `action.names`, `robot_type` 5 and
    {"a":1}, and 5 non-object roots. That gives **825 mutations**. For each one we called list,
    detail(x), detail(healthy), telemetry(x/0), append(x) with a connected robot, and replay(x/0).
  * **Results:**
    * list, detail, healthy and telemetry: 825 × 200 each. **0 5xx, 0 calls over 5 s.**
    * append: 706 × 409 `dataset_unreadable`, 9 × 422 `dataset_incompatible`, 110 × 200.
    * replay: 706 × 409 `dataset_unreadable`, 119 × 200.
    * **0 file changes on refused calls**, and the healthy dataset stayed byte-identical.
    * Station log: 0 tracebacks, 0 unhandled errors. Hub trap: no request.
  * **Accepted calls:** 109 of the 110 accepted appends were on mutations the Station still shows
    as finalized and readable (harmless fields such as `robot_type` or `splits`).
  * **2 flags, the same mutation (`total_episodes: 0`):** append and replay were accepted on a
    dataset the Station itself shows as not finalized. Replay of its closed data is harmless, but
    the append destroys data → **QH-9**.
* **Dev's fuzz:** `uv run --locked pytest -q tests/test_info_fuzz.py` in the fresh clone gives
  **1 passed** (18.7 s).

## Defects

| ID | Sev | Blocking | Origin | Summary |
|---|---|---|---|---|
| QH-9 | Medium | **yes** (data loss) | pre-existing (0.2.9 same) | An append into a dataset whose info.json under-counts `total_episodes` overwrites existing episodes |
| QH-6 | Low | no | CI flake (round 1) | Windows dead-man timing test; it passed in this round's CI |

* **QH-9 repro:**
  1. Copy a finalized dataset with 9 episodes in 5 data files.
  2. Set `"total_episodes": 0` in its `meta/info.json`, leaving everything else valid.
  3. Record → Append → that dataset → 1 episode.
* **Expected:** refused (409), files byte-identical. The Station's own page already says "not
  finalized (no episodes saved yet)" and lists 9 rows.
* **Actual:**
  * 200. `data/chunk-000/file-000.parquet` held episodes 0, 1 and 2 and now holds only the new
    episode 0.
  * **Episodes 1 and 2 are gone.** The page then shows episodes = 1, finalized = true, and rows 1-2
    "unreadable".
  * With `total_episodes: 3` (9 on disk) the append is also accepted, and that dataset even shows
    as finalized beforehand.
  * The published 0.2.9 wheel gives the identical result.
* **How it is reached:** neither LeRobot nor a crash produces this file. A crash leaves an empty
  or cut-short info.json, which 0.2.10 refuses, or files without a footer, which 0.2.10 also
  refuses. So in the field it needs a hand edit or a restored or merged folder.
* **Suggested guard:** refuse append (`dataset_not_finalized` / `dataset_unreadable`) unless
  `check_recording()` is complete **and** `total_episodes` equals the rows in `meta/episodes`.
* **Evidence:** `QH-9-data-loss.txt`, `fuzz_api_r3.txt`.
